# 04.安全地改写历史

`commit --amend`、`rebase`、`reset` 和历史过滤都会改变提交关系，并可能生成新的提交哈希。

## 操作边界

- 可以整理尚未共享的个人分支；
- 不要直接改写受保护分支或多人共享分支；
- 操作前执行 `git status`，并创建备份分支；
- 需要覆盖远程个人分支时使用 `--force-with-lease`。

```powershell
git branch backup/before-rewrite
git rebase -i origin/main
git push --force-with-lease
```

如果远程分支包含本地尚未见过的提交，`--force-with-lease` 会拒绝覆盖。先获取并检查：

```powershell
git fetch origin
git log --oneline --graph --decorate HEAD..origin/<branch>
```

## 恢复失败的改写

rebase 正在进行时可以执行：

```powershell
git rebase --abort
```

操作已经结束但结果不正确时，可以回到备份分支，或从 reflog 创建恢复分支：

```powershell
git reflog
git branch recovery <old-head>
```

先保留恢复引用，再决定是否重置当前分支。
