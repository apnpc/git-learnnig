# 07.仓库清理与敏感信息处理

从最新提交删除文件，不会删除历史对象。清理大文件、错误路径或敏感信息需要改写历史，所有受影响提交都会获得新哈希。

## 先处理泄露

敏感凭据一旦提交，应先在服务端撤销并轮换。历史清理不能让已经复制的秘密重新安全。

## 使用 git-filter-repo

`git filter-repo` 是独立工具，不随 Git 安装。请先阅读其文档，并在全新克隆中操作：

```powershell
git clone --mirror <url> cleaned.git
cd cleaned.git

# 分析仓库，不修改历史
git filter-repo --analyze

# 示例：从全部历史删除一个路径
git filter-repo --path path/to/secret.env --invert-paths
```

清理后必须检查所有分支和标签，再与协作者协调替换远程历史。旧克隆可能把被删除内容重新推回服务器，通常应要求所有人重新克隆。

不要直接在唯一副本上使用 `--force` 绕过全新克隆检查。

参考：[git-filter-repo 项目文档](https://github.com/newren/git-filter-repo)
