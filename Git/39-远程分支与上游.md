# 39.理解远程分支与上游

远程仓库、远程跟踪分支和本地分支是三个不同概念。

```text
服务器上的 main
       │ git fetch
       ▼
本地的 origin/main
       │ merge / rebase
       ▼
本地的 main
```

- `origin`：远程仓库的本地名称，可以改名，也可以配置多个远程仓库。
- `origin/main`：本地保存的远程跟踪分支，只在 `fetch`、`pull` 等操作后更新。
- `main`：可以直接提交的本地分支。
- upstream：某个本地分支默认对应的远程跟踪分支。

## 查看远程状态

```powershell
git remote -v
git branch -vv
git remote show origin
```

## 获取而不合并

```powershell
git fetch origin
git log --oneline --graph --decorate main..origin/main
git diff main...origin/main
```

`fetch` 更新 `origin/main`，不会自动改动本地 `main`。

## 设置上游分支

首次推送本地分支时：

```powershell
git push -u origin feature/login
```

`-u` 会把本地 `feature/login` 的 upstream 设置为 `origin/feature/login`。之后在该分支上可以直接执行 `git push` 和 `git pull`。

## pull 的集成策略

`git pull` 先执行 `fetch`，再按照配置集成上游分支。团队应明确选择策略：

```powershell
# 只允许快进，分叉时停止
git pull --ff-only

# 将本地提交变基到上游之后
git pull --rebase

# 使用合并方式
git pull --no-rebase
```

初学阶段推荐先执行 `git fetch`，检查差异后再明确选择 `merge` 或 `rebase`。
