# 38.撤销操作指南

撤销前先判断更改是否已经提交，以及提交是否已经共享。不同场景使用不同命令。

| 目标 | 命令 |
| --- | --- |
| 丢弃未暂存修改 | `git restore <file>` |
| 取消暂存，保留工作区修改 | `git restore --staged <file>` |
| 修改最近一次未共享提交 | `git commit --amend` |
| 撤销已经共享的提交 | `git revert <commit>` |
| 移动本地分支并保留修改 | `git reset --soft` 或 `git reset --mixed` |
| 找回误删的提交 | `git reflog` |

## 恢复工作区和暂存区

```powershell
# 用暂存区内容恢复工作区；未提交修改会丢失
git restore test.txt

# 用 HEAD 恢复暂存区，工作区修改仍保留
git restore --staged test.txt

# 同时恢复暂存区和工作区；两处修改都会丢失
git restore --source=HEAD --staged --worktree test.txt
```

执行会丢失未提交修改的命令前，先运行 `git diff` 和 `git diff --staged`。

## 撤销提交

已经推送或与他人共享的提交，应创建一个反向提交：

```powershell
git revert <commit>
```

只有尚未共享的本地历史才适合使用 `reset`：

```powershell
# 只移动分支；提交内容保留在暂存区
git reset --soft HEAD~1

# 移动分支；提交内容保留在工作区，这是默认模式
git reset HEAD~1

# 移动分支并丢弃暂存区和工作区修改
git reset --hard HEAD~1
```

## 使用 reflog 找回提交

`reflog` 记录本地引用移动历史。误用 `reset --hard` 后，只要对象尚未被清理，通常仍可恢复：

```powershell
git reflog
git branch recovery <lost-commit>
```

先创建恢复分支，不要再次执行破坏性操作。
