# 30.拉取并合并

`git pull` 先执行 `git fetch`，再按照参数和配置通过快进、merge 或 rebase 集成上游分支。

`git fetch` 根据 refspec 下载远程对象并更新 `origin/main` 这类远程跟踪引用。它们保存在本地，但不是可以直接提交的本地分支。`fetch` 不会自动改动当前工作分支。

`git pull --no-rebase` 使用 merge，`git pull --rebase` 使用 rebase，`git pull --ff-only` 只允许快进并在历史分叉时停止。

`git merge <branch>` 把指定分支集成到当前分支。它不会直接修改远程仓库，也不需要两个分支参数，因为目标就是当前分支。

以下是这些命令之间关系的总结：

- `git fetch`: 获取远程存储库中的最新代码更改，并将其保存在本地存储库中的 "remote branches" 中。
- `git pull`: 运行 `fetch` 后按选定策略集成上游分支。
- `git merge`: 将指定分支集成到当前分支；快进时不创建合并提交。

需要注意的是，尽管 `pull` 命令可以更快地获取远程存储库的最新代码更改并将其合并到本地存储库中，但它也可能会导致合并冲突。因此，在运行 `pull` 命令之前，请确保所有本地更改都已提交或保存。
