# 42.协作工作流

常见协作方式是：从主分支创建短期分支，完成一个独立改动，通过 Pull Request 审查后合并。

## 创建功能分支

```powershell
git switch main
git pull --ff-only
git switch -c feature/login
```

开发过程中保持提交聚焦：

```powershell
git status --short
git diff
git add <files>
git diff --staged
git commit -m "Add login validation"
```

首次推送并建立上游关系：

```powershell
git push -u origin feature/login
```

然后在托管平台创建 Pull Request。Pull Request 是拉取并审查分支更改的请求，不是“推送请求”。

## 保持分支最新

```powershell
git fetch origin
git rebase origin/main
```

只对自己的、尚未被其他人基于其继续开发的分支执行 rebase。更新已经推送的个人分支时使用：

```powershell
git push --force-with-lease
```

`--force-with-lease` 会在远程分支出现未知更新时拒绝覆盖；不要用无条件的 `--force` 覆盖共享分支。

## Fork 工作流

Fork 项目时，通常配置两个远程仓库：

```powershell
git remote rename origin fork
git remote add upstream https://github.com/ORIGINAL/REPOSITORY.git
git fetch upstream
git switch main
git merge --ff-only upstream/main
git push fork main
```

- `fork`：你有写权限的仓库。
- `upstream`：原项目仓库。

功能分支推送到 `fork`，Pull Request 的目标选择 `upstream` 的主分支。
