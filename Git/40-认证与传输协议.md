# 40.认证与传输协议

Git 常通过 HTTPS 或 SSH 访问远程仓库。两者传输的 Git 数据相同，区别主要在认证方式。

## HTTPS

```powershell
git clone https://github.com/OWNER/REPOSITORY.git
```

GitHub 等托管平台不再接受账户密码进行 Git 认证，应使用凭据管理器、浏览器登录或 Personal Access Token。不要把令牌写进远程 URL、脚本或仓库。

查看和修改远程地址：

```powershell
git remote -v
git remote set-url origin https://github.com/OWNER/REPOSITORY.git
```

## SSH

```powershell
ssh-keygen -t ed25519 -C "your_email@example.com"
ssh -T git@github.com
git remote set-url origin git@github.com:OWNER/REPOSITORY.git
```

只把公钥文件（通常以 `.pub` 结尾）的内容添加到托管平台。私钥不得发送给他人或提交到仓库。

## 发现凭据泄露

如果令牌或私钥进入了提交：

1. 立即在服务端撤销并重新生成凭据；
2. 删除当前工作树中的秘密；
3. 根据影响范围决定是否清理历史；
4. 通知已克隆仓库的协作者重新同步。

仅删除最新文件不能使秘密从历史记录中消失。
