# 37.比较更改

Git 的多数操作都围绕三个位置展开：

```text
工作区 --git add--> 暂存区 --git commit--> HEAD
```

`HEAD` 通常指向当前分支的最新提交。判断下一步该执行什么命令之前，先确认更改位于哪两个位置之间。

## 三种常用比较

| 命令 | 比较内容 |
| --- | --- |
| `git diff` | 工作区与暂存区 |
| `git diff --staged` | 暂存区与 `HEAD` |
| `git diff HEAD` | 工作区、暂存区与 `HEAD` |

例如，修改 `test.txt` 后：

```powershell
git diff
git add test.txt
git diff --staged
git commit -m "Update test.txt"
```

执行 `git add` 后，`git diff` 不再显示这次修改，因为工作区与暂存区已经一致；此时应使用 `git diff --staged` 查看即将提交的内容。

## 比较提交和分支

```powershell
# 比较两个提交的最终文件状态
git diff <old-commit> <new-commit>

# 查看当前分支相对 main 的更改
git diff main...HEAD

# 只显示发生变化的文件名和状态
git diff --name-status main...HEAD
```

`main...HEAD` 使用两个分支的共同祖先作为起点，适合在创建 Pull Request 前检查当前分支引入的更改。

## 提交前的最小检查

```powershell
git status --short
git diff --check
git diff --staged
```

其中 `git diff --check` 会检查尾随空格等常见空白问题。
