# 24.变基和合并

merge 和 rebase 都可以集成分支，但产生的历史不同。

假设两个分支从同一个提交分开：

```text
      C---D  feature
     /
A---B---E    main
```

## Merge

在 `main` 上执行 `git merge feature`，Git 通常进行三方合并并创建合并提交：

```text
      C---D
     /     \
A---B---E---M  main
```

如果 `main` 从分叉后没有新提交，合并可以直接快进，不需要合并提交。两个分支修改同一位置时，merge 会暂停并要求手动解决冲突。

适合：保留真实分支关系、集成共享分支。

## Rebase

在 `feature` 上执行 `git rebase main`，Git 会把 feature 独有的提交重新应用到 `main` 之后：

```text
A---B---E---C'---D'  feature
```

`C'`、`D'` 是新提交，哈希不同。rebase 也可能发生冲突，需要解决后执行 `git rebase --continue`；放弃使用 `git rebase --abort`。

适合：在合并前整理自己的、尚未共享的功能分支。

## 选择原则

- 已经共享、有人基于其继续开发的历史：优先 merge；
- 仅自己使用的短期分支：可以 rebase 到最新主分支；
- 团队规则优先于个人偏好；
- 不确定时，使用 merge，不要改写共享历史。
