# 41.跨平台文本与属性

Windows 常用 CRLF，Linux 和现代 macOS 常用 LF。只依赖每个开发者的本地配置，容易产生整文件变化；仓库应使用 `.gitattributes` 统一规则。

## 推荐配置

在仓库根目录创建 `.gitattributes`：

```gitattributes
* text=auto
*.sh text eol=lf
*.ps1 text eol=crlf
*.png binary
*.jpg binary
```

- `text=auto`：让 Git 自动识别文本文件并规范化存储。
- `eol=lf` 或 `eol=crlf`：指定检出到工作区时的行尾。
- `binary`：禁止文本转换和文本差异比较。

提交规则后，可以重新规范化已跟踪文件：

```powershell
git add --renormalize .
git diff --staged
git commit -m "Normalize line endings"
```

重新规范化可能产生大量改动，应单独提交，并先确认 `git diff --staged` 只包含预期的行尾变化。

## 可执行权限和大小写

Git 记录普通文件是否可执行，但不记录完整的操作系统权限。需要把脚本标记为可执行时：

```powershell
git update-index --chmod=+x script.sh
```

Windows 默认文件系统通常不区分文件名大小写，不要创建只靠大小写区分的两个文件，例如 `README.md` 和 `readme.md`。
